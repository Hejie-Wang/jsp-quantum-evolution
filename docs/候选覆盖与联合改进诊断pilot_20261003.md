# 候选覆盖与联合改进诊断 pilot（T01，Issue #19）

日期：2026-10-03。基线：PR #16 合并后 main（`e24f6bd`），依据 [PR #18 拆解文档](量子计算能否改善JSP问题的求解+子问题拆解TODO.md) 的 T01 工作包。执行：glm bot（jsp-agent-glm），PR 审查：deepseek。

**性质声明：本报告是诊断工具与 pilot 结果，全部数字来自本次实际运行并经独立校验；不含任何量子机制实验，不修改任何生产文件。**

## 范围与方法

T01 要求在冻结池上精确回答三个此前混在一起的问题：池里有没有比当前更好的解（ρ）、
要从当前标签改变多少台机器才能到达（d_imp）、以及"逐台换机器"的可行状态图能否
走进改进集（单机路径连通性）。本次 pilot 实现了完整诊断层并分两条线验证：

1. **D0 规模生成实例**（2×2、3×3、4×3，种子 0–9；每作业随机机器排列、工序时间
   独立均匀 1–9，按 PR #18 §3.1 规则生成并记录实例哈希）。每个实例构造
   全排列池（其池最优即实例精确 C*）与受限池（serial-SGS(mwr) incumbent 为
   候选 0 加随机排列，K∈{2,3}），对受限池做：全组合枚举（独立 Kahn 检查器）、
   ρ、d_imp、单机换标签图上的瓶颈 Dijkstra、以及池最优 MILP 交叉校验。
2. **D1 旧固定池报告**（`corrected_20261001` 的 15×15 / 15×20_derived / 20×15
   ×种子 7,11）。池规模 8^15–8^16，不可全枚举，因此只做：incumbent 的单机
   /双机交换邻域精确评价 + 池最优 MILP 重证。

独立检查器与生产解码器 `medium_qjsp.decode` 在全部窗口上一致；4 项单元测试
通过（`test_window_diagnostics.py`，含"枚举 == 逐项 decode 暴力"一致性）。

## 结果

### D0 验收与覆盖统计（受限池，每规模 20 窗口）

| 规模 | 枚举==MILP | 无改进池比例 | ρ 均值 | ρ 最大 | d_imp=1 | d_imp=∞ | 池最优>全局最优比例 | 池界-全局界 gap 均值/最大 |
|---|---|---|---|---|---|---|---|---|
| 2×2 | 20/20 | 20/20 | 0.0000 | 0.0000 | 0 | 20 | 0/20 | 0% / 0% |
| 3×3 | 20/20 | 14/20 | 0.0454 | 0.2963 | 6 | 14 | 9/20 | 6.49% / 30.43% |
| 4×3 | 20/20 | 17/20 | 0.0118 | 0.1250 | 3 | 17 | 18/20 | 18.91% / 43.33% |

- **T01 验收标准达成：D0 上 60/60 窗口枚举最优与 MILP 最优一致**（含
  `status=optimal` 与目标值逐项相等）。
- 60 个受限窗口中 51 个（85%）**池内不存在任何优于 incumbent 的组合**；
  其 d_imp=∞、单机换标签图不可达改进集。有改进的 9 个窗口全部 d_imp=1。
- 受限池的池最优普遍高于实例全局最优：4×3 上平均高 18.91%、最大 43.33%。
  这定量演示了"池界不是全局界"，直接支持 T02 必须独立建立合法全局下界。

### D1 旧固定池（8^15 量级，MILP 重证 + 邻域诊断）

| 窗口 | incumbent=报告最优 | MILP 池最优 | 单机交换（探索/可行/改进） | 双机交换（探索/可行/改进） | 邻域内最好 |
|---|---|---|---|---|---|
| ta01 (15×15) s7 | 1462 | **1462 =incumbent** | 105 / 23 / 0 | 5145 / 196 / 0 | 1722（更差） |
| ta01 (15×15) s11 | 1462 | **1462 =incumbent** | 105 / 15 / 0 | 5145 / 86 / 0 | 1694（更差） |
| ta21 派生 (15×20) s7 | 1675 | **1675 =incumbent** | 140 / 21 / 0 | 9310 / 201 / 0 | 1685（更差） |
| ta21 派生 (15×20) s11 | 1675 | **1675 =incumbent** | 140 / 25 / 0 | 9310 / 271 / 0 | 1685（更差） |
| ta11 (20×15) s7 | 1865 | **1835 <incumbent** | 105 / 18 / 0 | 5145 / 149 / 0 | 1865（无改进） |
| ta11 (20×15) s11 | 1865 | **1835 <incumbent** | 105 / 18 / 0 | 5145 / 149 / 0 | 1865（无改进） |

- **ta11 的池内隐藏联合改进**：MILP 证明池最优 1835，比当时报告的最好解 1865
  好 30（1.61%）；但 incumbent 的全部 5250 个单机/双机交换邻域组合中
  **没有一个优于 1865**。即到达 1835 至少需要同时改变 3 台机器的标签——
  这是"池内存在好解、但逐机器邻域搜索结构性够不到"的第一个实测样例，
  与 PR #18 §1 对旧固定池（1462 vs 1231）的推断一致并给出了新证据。
- ta01 / ta21 派生池的 incumbent 经 MILP 重证即池最优，且其单机/双机可行
  邻域全部更差（如 ta01 s7 最好邻域 1722 远差于 1462）：这些窗口的约束不是
  局部搜索深度，而是**池覆盖本身**。
- 全部 6 个窗口独立检查器与生产解码器对 incumbent 的可行性/工期判定一致。

## 与拆解文档论断的对照

| 文档推断（PR #18） | 本 pilot 证据 |
|---|---|
| 候选池覆盖可能比求解器更先构成瓶颈 | D1 四个池 incumbent=池最优且邻域全更差；D0 池界平均落后全局 6.5–18.9% |
| 存在联合改进但单机路径可能够不到 | ta11 池最优 1835 需 ≥3 机同时改变，单/双机邻域零改进 |
| 池界（L_Π / C_Π*）不得当全局界 | D0 上池最优>C* 的窗口占 45%（27/60），gap 最高 43.33% |

## 边界与未完成项（诚实清单）

1. **代理排序误差未计算**：代理目标属 T03 交付，此处刻意留空，不用占位数字。
2. **D0 身份与正式冻结属 T00**：本 pilot 的生成器按文档规则实现并记录哈希，
   但正式的数据身份核对、种子划分锁定以 deepseek 的 T00 PR 为准；届时受限池
   构造规则若调整，本表数字需按正式口径重跑。
3. **覆盖损失归因未做**：动态搜索中"过滤单机不可行候选、随机选机器"造成的
   覆盖损失需要插桩 `adaptive_search.py`；为遵守 Issue #19 的冲突规避约定
   （deepseek T00 正在修改该文件的 uniform 路径），本次未触碰。
4. ta11 s7 的 MILP 目标记录为 1835.0000000000064（求解器浮点噪声），整数
   工期按 1835 报告；`status=optimal`、对偶界一致。
5. 完整枚举层（≤20 万组合上限）只出现在诊断输出，未向任何在线算法提供。
