# D3/D4 基线界与公开界复现试点（2026-10-04）

依据 [PR #18 拆解文档](量子计算能否改善JSP问题的求解+子问题拆解TODO.md) 的 T02/T08 认证通道口径，在**本次新引入的标准实例**（[实例数据来源与核对T03D3D4_20261004.md](实例数据来源与核对T03D3D4_20261004.md)，PR #42）上做第一次基线界记录。执行：deepseek bot。

**性质声明：本报告只记录①平凡负载界（按定义合法）②在 `known_optimum − 1` 处的阈值判定结果。它**只复现**公开界，**不宣称任何新下界**；`UNKNOWN`/超时一律不抬界（T02 纪律）。**

## 1. 口径

| 项 | 值 |
|---|---|
| 平凡界 | `L0 = max(最大作业工时, 最大机器负载)`，由 `global_bounds.trivial_bound` 给出 |
| 完整模型 | `global_bounds.full_model_bound`（CP-SAT），时间上限见表 |
| 阈值探针 | `global_bounds.threshold_infeasibility(T = known_optimum − 1)`；**仅 `INFEASIBLE` 视为 `C* ≥ known_optimum` 的认证** |
| 探针时间 | 60 s（**低于协议规定的 600 s**，见 §3 边界） |
| 外部参考 | JSPLib `instances.json` 的 `optimum` 字段（用作评价，不作为本方法产出） |

三点可复核结论：

1. **`ta01` 完全复现公开界**：完整模型在 60 s 内给出 **OPTIMAL = 1231**，且 `T=1230` 的阈值判定为 **INFEASIBLE** → 认证 `C* ≥ 1231`，与 JSPLib `optimum` 一致。这是认证通道在新引入实例上的第一个端到端证据（**复现**，非新界）。
2. **`ta61` 的平凡负载界即为公开最优**：`L0 = 2868 = JSPLib optimum`，因此该实例无需搜索即被下界闭合（上界仍需可行排程验证）；这类"负载瓶颈"实例在 D4 里应单列，避免把"易闭合"混进方法收益统计。
3. **D3 两例（`ta30`/`ta40`）在 60 s 探针下未复现公开界**（`UNKNOWN`）。这不是"无法证明"，而是**探针预算远低于协议规定的 600 s**；同时完整模型在 300 s 内只给出对偶界 1450/1220，远低于 L0=1212/1602 与公开界 1562/1658 —— 说明这两个实例的认证需要长预算或专门的松弛通道（T08 的 `subset_relaxation_bound`）。

## 3. 边界与下一步

1. **探针预算 60 s ≠ 协议 600 s**：D3 的正式结论必须按 §3.2 在**固定 600 s、固定工作线程**下重跑 `ta30`/`ta40`；本报告只作为接口连通性证据。
2. **未做机器子集松弛对照**（`subset_relaxation_bound`）；T08 计划用它给 `ta30`/`ta40` 补合法界。
3. `ta61` 的闭合来自平凡界，**不得**记为方法收益；后续统计需把「L0 已闭合」的实例单列。
4. **无新下界宣称**；上表中"事后 L"列只取平凡界与已证阈值中较大者。
5. 真机（T09）保持 `not_executed`。
